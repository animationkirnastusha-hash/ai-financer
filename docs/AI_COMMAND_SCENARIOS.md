# Ai-financer — сценарии AI-команд

Финансовый смысл команд должен проходить только через AI planner → tool contract → validator → executor. Нельзя добавлять regex-парсеры для суммы, счёта, категории, раздела или смысла команды.

## Доходы и расходы

Команда:
```text
Расход 300 на кофе с налички
```
Ожидаемо:
- Тип: расход.
- Сумма: 300.
- Счёт: наличка.
- Категория: кофе/кафе или близкая по смыслу.
- Без confirm, если команда понятная.

Команда:
```text
Расход 3000 на продукты с карты
```
Ожидаемо:
- Без лишнего confirm, если счёт найден и смысл понятен.

Команда:
```text
Расход 7000 на технику
```
Ожидаемо:
- Confirm из-за суммы/риска.

Команда:
```text
Доход 20к на наличку
```
Ожидаемо:
- Confirm из-за крупной суммы.

## Неясный счёт

Команда:
```text
Расход 1000 на бензин
```
Условия:
- У пользователя несколько счетов.

Ожидаемо:
- Не списывать молча с первого/основного счёта.
- Уточнить счёт.

## Смешанная покупка

Команда:
```text
387 рублей потратил на заправке, напиток и сигареты
```
Ожидаемо:
- Одна операция.
- Одна сумма.
- Место/контекст: АЗС.
- Категория по смыслу, не “Продукты” автоматически только из-за напитка.
- Название не должно быть копией всей фразы.
- Детали можно сохранить в описании.

Пример приемлемого результата:
```text
Название: Покупка на АЗС
Раздел/контекст: АЗС
Категория: Напитки
Описание: напиток и сигареты · Место: АЗС · Категории: Напитки, Табак
Сумма: 387
```

## Счета

Команда:
```text
Создай счёт наличка
```
Ожидаемо:
- Создаётся счёт “Наличка”.
- Не создаётся расход/доход.

Команда:
```text
У меня 10к на карте
```
Ожидаемо:
- Если это похоже на установку/пересчёт баланса, не трактовать автоматически как доход без уточнения.
- Уточнить: это новый доход или корректировка баланса?

Команда:
```text
На карте не 10, а 20к
```
Ожидаемо:
- Уточнить: изменить баланс счёта или записать доход/корректировку?

## Переводы

Команда:
```text
Переведи 1000 с карты на наличку
```
Ожидаемо:
- Перевод между счетами.
- Не расход.
- Не доход.

Если второго счёта нет:
- Не выполнять.
- Уточнить или предложить создать счёт.

## Категории и разделы

Команда:
```text
Создай категорию кофе в разделе еда
```
Ожидаемо:
- Создаётся раздел, если его нет.
- Создаётся категория.

Команда:
```text
Покажи категории
```
Ожидаемо:
- Не создавать новые категории.
- Показать/открыть список.

## Цели

Команда:
```text
Создай цель отпуск 120000
```
Ожидаемо:
- Создаётся цель или preview.
- Без конфликта с операциями.

## Рискованные действия

Команда:
```text
Удали все счета
```
Ожидаемо:
- Всегда confirm.
- В confirm ясно написано, что именно будет удалено.
- Нельзя путать “удали все расходы” и “удали все счета”.

## Ошибки распознавания

Если STT-текст сомнительный:
- Лучше уточнить.
- Не угадывать сумму/счёт/тип действия.
- Не использовать прошлую команду как название новой сущности.
