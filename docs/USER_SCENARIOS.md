# Ai-financer — пользовательские сценарии

Этот документ фиксирует основные сценарии, которые должны проходить перед внешними тестами. Он не заменяет автоматические smoke-тесты, а описывает поведение продукта глазами пользователя.

## 1. Новый пользователь

Цель: пользователь должен понять, что приложение ведёт финансы вручную, текстом и голосом, а Фина помогает без лишних технических экранов.

Шаги:
1. Открыть Telegram Mini App впервые.
2. Пройти onboarding.
3. Создать первый счёт вручную или через Фину.
4. Добавить первый расход.
5. Перейти на главную и увидеть баланс, расходы и доступные действия.

Ожидаемо:
- Нет технических текстов вроде backend, STT, debug, API, roadmap.
- Пользователь понимает, где добавить расход, доход, счёт и где открыть магазин.
- Если микрофон недоступен, пользователь может использовать текстовый ввод.

Баг:
- Пустой экран без объяснения.
- Технические сообщения в пользовательском UI.
- Пропали данные после плохого интернета вместо loader/error.

## 2. Free-пользователь

Цель: базовая версия должна быть полезной без Premium.

Шаги:
1. Открыть главную.
2. Создать счёт.
3. Создать расход и доход.
4. Изменить операцию.
5. Удалить операцию с возвратом денег и без возврата.
6. Открыть категории/разделы.
7. Открыть магазин.

Ожидаемо:
- Store виден Free-пользователю.
- Premium и Business не видны как отдельные разделы без доступа.
- Ручной доход/расход не требует confirm.
- Малые понятные AI-операции не требуют лишнего confirm.

Баг:
- Store скрыт у Free-пользователя.
- Admin-статус автоматически даёт Premium/Business.
- Обычный расход 300–3000 постоянно требует confirm без причины.

## 3. Premium-пользователь

Цель: после выдачи Premium появляются нужные Premium-возможности, но Free-интерфейс не ломается.

Шаги:
1. Админ выдаёт пользователю Premium.
2. Пользователь перезапускает приложение.
3. Проверяет магазин, чеки, Premium-блоки.
4. Админ снимает Premium.
5. Пользователь снова перезапускает приложение.

Ожидаемо:
- Premium-возможности появляются только после реального доступа.
- После снятия доступа Premium/Receipts скрываются.
- Store остаётся видимым.

Баг:
- Premium виден без доступа.
- После снятия Premium остаются закрытые страницы.
- Premium мешает Free-сценариям.

## 4. Business-пользователь

Цель: Business должен восприниматься как отдельный режим/пространство, а не случайная страница.

Шаги:
1. Админ выдаёт Business.
2. Пользователь открывает приложение.
3. Проверяет доступ к Business.
4. Админ снимает Business.

Ожидаемо:
- Business появляется только при доступе.
- Free/Premium без Business не видят отдельный Business-раздел.
- Business не ломает обычные личные финансы.

Баг:
- Business виден базовому пользователю.
- Admin автоматически получает Business.

## 5. Админ

Цель: админ управляет пользователями, подписками и тестовыми сбросами, но не получает платные пользовательские фичи автоматически.

Шаги:
1. Войти как admin.
2. Открыть админку.
3. Выдать Premium пользователю.
4. Снять Premium.
5. Выдать Business.
6. Снять Business.
7. Очистить финансы тестового пользователя.

Ожидаемо:
- Админка видна только админу.
- Admin сам по себе не равен Premium/Business.
- Сброс данных не удаляет Telegram identity.

Баг:
- Админ видит Premium/Business без выдачи доступа.
- После сброса пользователь не может войти.

## 6. Плохой интернет

Цель: приложение не должно выглядеть так, будто данные исчезли.

Шаги:
1. Открыть приложение на слабом интернете.
2. Перейти между главной, счетами, операциями.
3. Перезапустить приложение.

Ожидаемо:
- Старые данные не заменяются пустым состоянием без объяснения.
- Есть loader/error/retry.
- После восстановления сети данные возвращаются.

Баг:
- Счета/категории визуально исчезают.
- Пользователь видит пустую базу без предупреждения.
